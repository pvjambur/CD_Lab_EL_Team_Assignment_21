LLVM Compiler Instrumentation · Dynamic Numerical Stability Analysis

Compile-Time Floating-Point Error Detection Engine

This verification environment operates in two execution modes: Simulated (pure JavaScript in-browser floating-point modeling) and Live Toolchain (direct execution of the custom nsan-clang++ compiler wrapper, the LLVM pass plugin libnsan_pass.so, and the shadow memory runtime library libnsan_runtime.a). Connecting the local verification server unlocks live compiler execution and dynamic numerical analysis.

1Compiler Transformation & Execution Pipeline

Source code remains unmodified throughout the pipeline. The sanitizer intercepts the intermediate representation (LLVM IR) during optimization, clones scalar floating-point instructions into parallel double-precision shadow operations, and forwards the instrumented module to code generation.

2Intermediate Representation Instrumentation

Simulated mode demonstrates the textbook SSA transformation pattern. Live Toolchain mode compiles the target source module twice — once using standard uninstrumented clang++ -O1 and once using -fpass-plugin=libnsan_pass.so — to display the exact three-column transformation produced by the pass.

Instrumentation Phase Breakdown (3-Step Pass Transformation)
1. SHADOW MATH

Every 32-bit float arithmetic instruction (fadd, fsub, fmul, fdiv) is intercepted. Operands are extended to 64-bit (fpext to double) and evaluated in parallel high precision.

2. SHADOW MEMORY

When floating-point variables are stored or loaded (alloca, store, load), calls to __nsan_shadow_ptr_store and load synchronize the 64-bit shadow double in TLS shadow memory.

3. CONSISTENCY CHECK

Before critical branches, returns, or stores, __nsan_check_consistency(float %z, double %z.shadow) verifies if |f - d| / |d| > ε. If divergence exceeds threshold, a warning fires to stderr.
